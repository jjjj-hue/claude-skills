# Week 2 (W29): Jul 13–15, 2026 — The Audit Turns Inward

**Tagline:** Three days that started as a plugin cleanup and ended with Claude tracking its own processes at 11pm — while, underneath it all, five site monitors got built, a security leak got plugged, and the 232 Elizabeth flip quietly stopped being a single campaign and became infrastructure.

## Narrative

Week 1 ended with a self-audit wave — plugin bloat, skill usage stats, a Composio experiment — standing up faster than anyone could tell what would stick. Week 2 answers that question, mostly by doubling down. At 1:51am Jul 13, before the sun's even a consideration, Claude is already writing a listing-monitor pattern with HTML parsing and email alerts. Two hours later it's running a full "claude-prospector" audit: 119 agents, 543 skills, heavy duplication, 84% bloat traced to dev-tooling plugins nobody in the Bond NY workflow ever calls (S254, obs 103). The finding sharpens fast — 18 enabled dev skills, zero invocations across 324 sessions (108) — and this time it produces action, not just another chart: a `cdev` alias and a settings.dev.json split separate real-estate sessions from dev-tooling sessions (122, 139), and ~/.claude gets git-initialized for the first time (175) so the configuration itself has a history. An orphaned ECC plugin gets hunted through cache directories and confirmed gone (129–131), 188MB of stray clone folders get swept (152). This is the audit paying off — Week 1's "unclear which get adopted" resolves toward adopted.

But the same instinct that cleans also compounds. By late Jul 13 the session log is a wall of near-duplicate titles — "catchup," "audit sessions," "which can be safely closed" — appearing five and six times in an hour (S284, S289, S292, S296, S374, S388). This isn't new user frustration; it's Claude checking its own work by re-deriving it, over and over, a pattern that becomes the week's real signature. It peaks Jul 15 night: PID 6721 mapped to ttys001, transcript file sizes compared byte for byte (7.3MB vs 397KB), a "duplicate session" investigation of a session investigating duplicate sessions (498–502, S420–422, S441–442). The tooling built to audit usage has started auditing its own auditing.

The security thread resolves cleanly, though. Jul 14 afternoon turns up multiple FollowUpBoss API keys sitting in plaintext across config and history files (316) — then, methodically, five separate removal passes strip deprecated keys out of settings.local.json's permission allowlist (318–322). Jul 15 repeats the pattern for GitHub: a deprecated MCP package gets swapped for the official remote server (370), then a PAT found hardcoded in settings.json gets rotated to Keychain-based sourcing — twice, because a second hardcoded copy turns up after the first fix (411–420). Two real vulnerabilities, found and closed in the same week they were found.

The site-monitors project is the week's actual build. What started as "replicate the MC pattern" becomes six target properties — Mercedes House, MetroNest, Marc Leasing, Clipper, Greenpoint, The Max — each fighting its own scraping villain. Mercedes House gets migrated from raw HTML scraping to a real Nestio API (273). Marc Leasing turns into a multi-hour reverse-engineering session: Firecrawl fails, direct curl fails, StreetEasy's Next.js props hide the data, browser automation finally catches a GraphQL POST pair mid-flight (455–463) — a satisfying, hard-won extraction. MetroNest gets a formatting pass and ships to git same day (470–474). Greenpoint runs into exhausted Firecrawl credits, pivots to a RoseNYC iframe with clean static HTML (S429), and becomes the week's last big build, ending in a genuinely funny loop: fix iOS address auto-linking with zero-width spaces, discover it regresses, replace it with styled hyperlinks instead, discover *that* has a gap too, and end the week pending a manual Gmail-app check before committing (S434–S442).

232 Elizabeth's Vol4 never gets a "sent" observation this week either — but it stops being asked for one. The flip campaign dissolves into the qualified-bank.md tracker, which gets reorganized into a 65-unit interactive dashboard (S324) and, by Jul 15, synced to Google Drive as a real shared spreadsheet (398–399). Ric's own rics-listings.md gets a genuine fix, too: a "Flips" section header was causing his comp-only units to look like sendable recommendations, quietly mislabeled since week one — renamed to "Comp Bank" with an explicit non-recommendation warning (491). And the StreetEasy data-quality thread from Week 1 escalates into its own verification project: 102 Bond NY 2BR listings checked in parallel, turning up rented units, address mismatches, and delisted listings at real scale (232–258) — confirming that bad source data, not campaign mechanics, was the actual bottleneck all along.

## Where We Are

As of Jul 15 night, the workspace has more real infrastructure than it did a week ago: a git-tracked ~/.claude config, a real dev/business settings split, two closed credential leaks, and five (soon six) working site monitors feeding email alerts off live scrapes. qualified-bank.md is now a shared, Drive-synced spreadsheet instead of a loose markdown file, and a real mislabeling bug in rics-listings.md — one that could have sent a client a comp-only unit as a live recommendation — got caught and fixed. The StreetEasy data-quality problem is now understood as systemic rather than anecdotal, verified across 100+ listings.

What's still open: the Greenpoint monitor's styled-hyperlink email format is unverified and uncommitted; the same fix needs backporting to four other monitors before the six-monitor build can be called done. The Composio-FUB OAuth integration was started and never confirmed working — it's unclear if it's still wanted. No observation in either week confirms a 232 Elizabeth flip email actually going out to leads; the campaign's energy moved into tracker infrastructure instead, which may or may not have been the point. And the recurring pattern of Claude re-auditing its own concurrent sessions — sometimes several times an hour — hasn't been named as a problem by Lucia, but it hasn't stopped either. The next chapter isn't written yet; these are simply the open threads at the point the record stops.
